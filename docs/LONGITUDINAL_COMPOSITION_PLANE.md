Status: real longitudinal L3B materialized and approved for bounded downstream commissioning, 2026-09-30.

## Contract and boundary

C5 materializes:

```text
research.eph-longitudinal-composition-plane/v1
```

from one exact parent release of:

```text
research.eph-longitudinal-analysis-frame/v1
```

The grain is exactly one output row per C2 `row_id`. C5 does not reconstruct C2
identity, panel linkage, geography, or raw-source lineage. The output copies the
C2 identity/lineage columns in source order and verifies an exact sequence hash
over:

```text
row_id
household_observation_id
panel_household_id
period
region_id
source_release_id
source_row_identity
```

No income/welfare target and no current individual labor state is a named C5
model feature.

## Reuse of the reviewed compiler

C5 imports the existing EPH-side `_transform_series` implementation from
`aligner.real_semantic_plane`. It does not contain a second table of P02/P03/P05
or housing recodes.

The exact 2024-Q3 + CPV-2010 policy is used in two distinct ways:

1. approved canonical recode definitions are reusable compiler definitions;
2. the exact-pair semantic approval itself is **not** promoted to historical
   longitudinal approval.

The release manifest records both facts. Fixture/compiler-only releases retain
`reusable_recode_compiled_longitudinal_approval_pending_l3b`; the real L3B
materializations bind the governed historical-special policy and carry explicit
longitudinal approval for their exact 37-quarter parent.

## Period × concept support inventory

C5 verifies the C2 `schema_inventory.csv`, reconstructs person/household source
support by period, then emits one `support_inventory.csv` row for every
`period × profile concept`.

Each row records:

- raw EPH field and resolved C2 column;
- source role (person/household);
- observed raw and canonical support;
- unexpected codes and impossible canonical values;
- declared special-to-null/special-map handling;
- row/null/non-null counts;
- exact-pair semantic decision and temporal role;
- longitudinal review status;
- cross-survey approval status;
- `longitudinal_approved` reflecting the exact release's L3B adjudication state.

A raw field absent from a period's C2 source schema fails before materialization.
An unexpected code or impossible transformed value fails immediately. A unioned
C2 column that is blank because the source field was absent cannot masquerade as
support because support is checked against C2's period-specific schema ledger.

## Census compatibility hook

`aligner.census_profile_hook.census_named_profile_frame(...)` projects the same
registry against the canonical columns already generated by the existing real
CPV semantic compiler. It performs no Census recoding itself.

`P1R_NOLAB_LONG` is compatible with the current CPV-2010 compiler. `P0_LONG`
fails closed because CH07 has no approved Census concept.

This proves feature-identity compatibility only; it does not establish temporal
admissibility or statistical transport.

## Release payload and lineage

A release contains:

```text
composition_plane.csv
support_inventory.csv
profile.json
profile_registry.json
semantic_policy.json
parent_manifest.json
qa.json
manifest.json
checksums.sha256
```

The release ID is content-addressed by the exact C2 release/manifest/person
hashes, semantic-policy hash, profile-registry hash and profile ID. Existing
release directories are immutable.
